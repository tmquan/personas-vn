# Data exploration — what the curator pipeline's terminal artefact looks like

A static, reviewable rendering of [`DATAEXPLORATION.ipynb`](DATAEXPLORATION.ipynb)
that you can read without a notebook server. The notebook is the source
of truth — every figure here was generated by re-executing it under
`docs/figures/exploration/` and then embedded inline below. To regenerate:

```bash
conda activate pgm                                       # one-time setup: see README
pip install -e ".[curator,viz,dev]" "kaleido>=1.0,<2.0"
python -m packages.pipeline.cli curate                   # populates data/nso-gov-vn/
python -m scripts._build_dataexploration_nb
jupyter nbconvert --to notebook --execute DATAEXPLORATION.ipynb --inplace
```

Where [`DATAANALYSIS.md`](DATAANALYSIS.md) plots the **raw curated data**
as distributions and time-series, and [`DATAVISUALIZATION.md`](DATAVISUALIZATION.md)
plots them on the **map of Vietnam**, this document explores the
**curator pipeline's terminal artefact** — `data/nso-gov-vn/reduced/reduced.parquet`,
a 502-row table that places every PX-Web matrix in a 2-D UMAP space
alongside its statistical domain, HDBSCAN cluster, and embedding-derived
metadata.

## Executive summary

| Stat                                            | Value          |
| ----------------------------------------------- | -------------- |
| PX-Web matrices placed in UMAP 2-D              | **502**        |
| Embedding model                                 | `paraphrase-multilingual-MiniLM-L12-v2` (384-d) |
| Reducer                                         | UMAP `n_neighbors=15`, `min_dist=0.10`, cosine  |
| Clusterer                                       | HDBSCAN (auto `min_cluster_size = max(5, n // 80)`) — **opt-in** via `reduce.cluster: true` (default off) |
| Ontology domains covered                        | **12**         |
| Median table size (cells)                       | **~250**       |
| Earliest year of data                           | **1986**       |
| Latest year of data                             | **2024**       |
| Mean per-cluster dominant-domain purity         | **>50 %**      |

**Key findings** (each backed by a figure below):

1. **Health (97), trade (72), agriculture (70), and population (63)
   are the four largest ontology domains** — together >60 % of the
   catalog (§1).
2. **Median PX-Web table is ~250 long-format cells**; the right tail
   (>10K cells) is dominated by the V02.03–07 demographic cross-tabs
   (§2).
3. **National Accounts (V03) and Health & Society (V14) reach back the
   furthest** (1986 / 1995); Enterprises (V05) and recent multi-
   dimensional poverty cuts (V14.45) are the youngest series (§3).
4. **`Năm` (year) and `Tỉnh, thành phố` (province) appear in nearly
   every table** — every cell in the catalogue can be sliced as a
   time-series and joined against the 63-province admin base (§4).
5. **Unsupervised HDBSCAN clusters (density-based, on 384-d MiniLM)
   reconstruct most of the supervised ontology** when enabled (§10) —
   every dense cluster's dominant domain accounts for the majority of
   its members. Clustering is **opt-in** in the curator pipeline
   (`reduce.cluster: true`); the default keeps it off and §10
   skips. Low-density points (when present) are surfaced as noise
   (`-1`) rather than forced into clusters, so purity isn't
   inflated by KMeans-style forced assignments.
6. **Vietnamese-language semantic signal survives the multilingual
   MiniLM**: nearest-neighbour search returns same-domain peers even
   when the anchor and neighbour share zero literal vocabulary (§11).

## §1 — Catalog overview — tables per domain, stacked by database

How many PX-Web tables sit under each statistical domain, broken down
by database. The 12 NSO databases (`V01` – `V15`) are the actual
folders the catalog is organised in; the 12 ontology domains
(`population`, `agriculture`, `industry`, …) are our normalised
mapping over them. The two largely line up — but a single database
can fan out to multiple domains (e.g. `V14` — Health, Society, Living
Standards — splits across `health`, `education`, and `other`) and
that's where the ontology mapping pulls its weight.

## §4 — Variable signatures — top-30 PX-Web variable codes

Each PX-Web matrix declares its dimensions in `metadata.variables[*].text`
— things like `Năm` (year), `Tỉnh, thành phố` (province), `Giới tính`
(sex), `Nhóm tuổi` (age group). These are the table's "schema
fingerprint" and they're how the embedding can tell apart, say, a
province-level employment table from a province-level industry table.

![Variable signatures](docs/figures/exploration/04_variable_signatures.png)

## §5 — TF-IDF keyword landscape

The extract stage runs a Vietnamese-friendly TF-IDF (1–2 grams,
`token_pattern=r'(?u)\b[\wÀ-ỹ]{3,}\b'`) over every synthesised table
descriptor. The terms below are the ones that stuck out most across
the catalog — they're a peek at what the embedder considers
*distinctive* signal, not what's frequent (frequent terms like `Năm`
and `tỉnh` are filtered out by the high `max_df=0.85` cap).

## §7 — UMAP scatter × NSO database (12 colours)

Same UMAP layout, recoloured by the **NSO database** the table was
crawled from (`Dân số và lao động`, `Doanh nghiệp`, `Nông, lâm
nghiệp và thủy sản`, …). Database is the raw file-system
organisation NSO publishes; §6's `domain_id` is our normalised

## §10 — Cluster purity — does unsupervised HDBSCAN recover the ontology?

**Opt-in section** — only populates when the curator pipeline was
run with `reduce.cluster: true` in `configs/curator.yaml` (default
is `false`). The figure below was rendered against a curator run
with clustering on; with the default off, the matching notebook
cell prints "clustering: off in curator pipeline" and the figure
is skipped.

For each HDBSCAN cluster (noise points labelled `-1` are dropped),
the bar height is the share of its tables that fall under the
cluster's dominant ontology domain (the legend above each bar shows
which domain). A bar at 100 % is a domain the embedding discovered
on its own; a bar at 60 % is a real multi-domain neighbourhood
(often "trade × industry" or "health × education"). Unlike KMeans —
which would force every table into a cluster and inflate purity —
HDBSCAN refuses to assign low-density points, so the purity figure
here only reflects the dense regions the algorithm is confident
about.

![Cluster purity](docs/figures/exploration/10_cluster_purity.png)

## §11 — Semantic neighbour search

The 384-d MiniLM embedding is what lets the visualizer's "Curator"
tab support free-form Vietnamese queries (`"thu nhập theo tỉnh"` →
returns the 5 most-similar PX-Web tables). Below: pick four anchor
tables (V02.01 population, V03.01 GDP, V07.01 industrial output,
V14.45 multidimensional poverty), look up their five nearest
neighbours in cosine space, and project each anchor + neighbours
group onto the same UMAP plane.

This is also the test that *the embedding actually carries semantic
signal* — neighbours should share both database and statistical
content, not just orthography. They do: V03.01 ("GDP") falls near
V03.13 ("state budget revenue") which shares zero surface tokens but
co-clusters tightly on national-accounts narrative.

![Semantic neighbours](docs/figures/exploration/11_semantic_neighbours.png)

## Summary

* **502 PX-Web tables** in the catalog, normalised onto **12 ontology
  domains** via `OntologyRegistry.map_nso_category()` over the
  database name. Health (97), trade (72), agriculture (70) and
  population (63) are the largest domains.
* **326,692 long-format cells** total. Median table is ~250 cells; the
  deepest (V02.03–07) is ~10,400 cells.
* **MiniLM 384-d embedding** + UMAP into 2-D is always written;
  density-based HDBSCAN clustering is **opt-in** via the curator's
  `reduce.cluster: true` flag (default off). When on, §10 shows
  every dense cluster's dominant ontology domain accounting for the
  majority of its members and HDBSCAN's noise points (`-1`) are
  documented separately so the purity figure isn't inflated by
  forced groupings.
* **Vietnamese-language signal survives** the multilingual MiniLM
  encoder: the nearest-neighbour search in §11 returns same-domain,
  same-aggregation-level peers for every anchor we tried, including
  queries that share zero literal vocabulary (e.g. `V03.01` "GDP" →
  near `V03.13` "state budget revenue", which share no surface tokens
  but co-cluster on "national accounts").
